## Architecture

- Subsidy Optimization owns optimization behavior, scenario evaluation, recommendation selection, lifecycle, and reproducibility evidence.
- Platform configuration infrastructure owns effective-date, scope, and version resolution.
- Policy, Model, and Strategy are separate typed governed configuration assets.
- Configuration resolves before scenario generation and directly controls thresholds, subsidy amounts, load limits, penalties, objective weights, tolerances, scenario factors, and search bounds.
- Metering and Utility Rating are consumed only through published business-neutral contracts.
- Infrastructure adapts aggregate persistence and runtime composition; Host owns authenticated delivery.
- No caller-supplied policy values, optimizer weights, or strategy factors enter the API contract.

## Architect Verification Remediation

- Movement-budget invariant: one domain-owned allocation invariant now computes transferred units and enforces conservation and the governed property-wide movement budget independently across generation, evaluation, and completion evidence.
- Mandatory subsidy cliffs: every configured policy cliff is included unconditionally before optional strategy candidates, so the scenario limit cannot remove an approved economic discontinuity.
- Objective materiality: scenario cost is derived from governed Utility Rating amounts and units, while configured penalties and property load and movement impacts remain material soft-objective terms; per-meter sanctioned loads remain hard constraints.
- Domain completion and evidence invariant: aggregate completion independently recomputes configuration role and scope, meter participation, conservation, sanctioned load, movement budget, selected scenario, and rounded monetary outcome consistency from immutable execution evidence.
- Meter participation: only active, supported consumption meters participate; unsupported statuses, rating-only meters, and ratings not correlated to a participating meter are rejected before forecasting and persisted evidence uses the normalized participant set.
- Trusted authorization scope: execute, read, recommendation, and archive handlers use the existing decorated authorization path and resolve property scope against the trusted current-user context rather than accepting request values as authorization evidence.
- Policy, Model, and Strategy payloads remain strictly validated before estimation, scenario generation, or evaluation begins.
